# R3 reconciliation patch semantics

Provider A/B persistence/signing/consume ordering are unchanged except startup snapshot reconciliation and preservation helpers. Exact snapshot accepted. Snapshot seq below current ledger is recovered only after its head AND complete nonce-bearing spent map equal the validated ledger prefix at that sequence. Ahead => snapshot_ahead_of_ledger. Equal sequence mismatch => snapshot_equal_seq_divergent. Older non-prefix => snapshot_not_valid_prefix. Parseable invalid schema => snapshot_structure_invalid. These errors abort before server creation without modifying ledger or snapshot.

Missing snapshot rebuilds from valid authoritative ledger, reason missing_snapshot. Invalid JSON/UTF-8, duplicate JSON keys or nonfinite constants are malformed: exact bytes are saved to <snapshot>.malformed.<sha256>.bin using exclusive creation, flush/file fsync/directory fsync before atomic snapshot replacement. Existing archive is accepted only if byte-identical. Preservation failure aborts; ledger remains unchanged. Parseable schema/history discrepancies never enter this recovery path. Unreadable snapshot fails snapshot_read_error. Recovery is logged with archive path when applicable.

Offline pure tests cover exact agreement, genesis/nonempty prefixes, ahead/equal-head/equal-spent/older-nonprefix rejection and malformed parsing. These do not execute startup/persistence or emulate Linux. R3 runtime adds only S04 ahead and S05 head/spent startup failures to existing S00–S03; S03 retains valid-prefix recovery. Malformed snapshot archive recovery is documented/static and is not claimed as an added Linux experiment.

R3 raw startup exit/listener-probe observations and pre-restart restored snapshot bytes are retained; run captures candidate manifests/harness identity. R1/R2 pins are checked before and after the simulation. Both ledger+snapshot rollback to older mutually consistent history remains outside the established property. No crash/power-loss/concurrency/reboot/relay-failure scope was added.
