# AE001 — Provider-Controlled Artifact Exchange

Revision 1. Candidate for preflight; locked before scored execution by AE001_LOCK_SHA256SUMS.txt.

Property: request-bound provider-issued verification material traverses an intermediary without making the intermediary the evaluator or execution authority. The target provider alone evaluates it, initiates its software execution and produces authenticated boundary signals. The association records those signals and cannot thereby authorize execution.

Topology: requester on Xer0trust/Windows 192.168.1.102; relay and a separate association-recorder process on nuvl-relay/Pi 192.168.1.100 (ports 18080 and 19191); Provider A on Xer0trust-3/Linux 192.168.1.118 and Provider B on Xer0trust2/Linux 192.168.1.107 (port 19090 each). Use isolated /home/seth/ARTIFACT_EXHANGE/RUN_ID directories. No canonical MP003 source or state is changed. The Pi deployment includes relay source, association source and public trust material only. Providers receive their own laboratory keys and sources; issuance utilities run on the corresponding provider host. The requester transports already-issued artifacts.

Implementation: exact MP003 role/mint/registry/key source copies, identified in AE001_SOURCE_MANIFEST.json. AEBS.py is the architectural reference. Its illustrative fixed token and unsigned printed boundary hashes are not treated as the authenticated AE001 implementation. scripts/launch_role.py selects hosts, ports, fresh run-state paths and an observational outbound urllib audit hook. It does not replace role methods or alter provider decision logic. The relay computes request representation/binding and mechanically fans out the appropriate opaque authorization-header value. It does not decode provider authorizations, evaluate policy, sign boundary packages or receive boundary signals. The association receives signals directly from providers. Transient transport threads/queues are not scored as a statelessness property.

Existing format: request_repr=SHA256(exact request bytes); binding=SHA256(UTF8("NUVL_BIND_V1|"+request_repr+"|"+context)); operation_id=SHA256(UTF8("NUVL-MP-OP-v1|"+binding)). Issuance ID/signature and boundary signature use unchanged MP003 canonical JSON and domain tags. Ed25519 issuance keys are separate from boundary keys. No new binding scheme is introduced.

Only these four cases, in order, target B through X-Provider-B-Authorization. X-Provider-A-Authorization is absent throughout; A's ordinary authenticated DENY auth_missing is background path evidence, not an additional case. Each case has a new request/run nonce and a fresh issued authorization. N01 preserves its unaltered original separately.

| Case | Presented material | Required B outcome |
|---|---|---|
| B01 | Legitimate B issuance, matching fresh request | signed START, one software execution, signed COMPLETE; exactly one new spent authorization |
| N01 | Legitimate fresh B package with the first decoded signature byte XOR 1; all authorization fields unchanged | signed DENY auth_bad_sig; B spent/execution files byte-unchanged; no START/COMPLETE |
| N02 | Legitimate fresh A authorization placed in B header | signed DENY auth_provider_mismatch; B spent/execution files byte-unchanged; no START/COMPLETE |
| B02 | Legitimate fresh B issuance after negatives | signed START, one software execution, signed COMPLETE; exactly one new spent authorization |

Initial state is explicitly created only in each new run's runtime directory. Final expected counts: A zero executions/spent; B two executions/spent. Preserve absence of an execution log separately from a zero-byte representation in snapshots. Do not erase/reprovision prior state. The unchanged provider's own atomic persistence updates are confined to its fresh run state; no historical files are targets.

PASS requires all four outcomes, verified provider-specific raw boundary signatures/key identities, matching request/binding/operation/authorization/nonces, relay outbound artifacts matching exact headers and request derivations, and per-case execution/state confirmation. Relay audit entries show outbound construction attempts; correlated provider-signed results and provider state establish receipt/evaluation. HTTP 204 alone never establishes execution. The recorder's classifications are not the signature-verification oracle. Require 10 submissions (four background A denials and six B events), plus recorder SESSION_START/SESSION_END. No chronology or association-chain claim is derived from these records.

Unexpected admission, wrong-provider execution, unauthorized state consumption or observed intermediary fabrication is FAIL. Missing delivery, missing evidence or a broken precondition is INCOMPLETE. Any source/configuration change after locking requires a retained revision and new lock before scoring; expected reasons cannot be rewritten after a run. A preflight misfire is retained and recorded in CHECK_ME. Preflight and scored runs use distinct fresh directories.

Required evidence: exact request bytes, issued and sent authorization packages/header values, issuer output, relay delivery records, provider raw signed packages, association records, before/after provider state and execution files (with presence metadata), runtime consoles, deployment/source hashes, canonical MP003 state hash bookends, scorecard and SHA256SUMS. Preserve all failures. Laboratory keys remain for reproduction. Freeze source/launcher/harness hashes and topology in AE001_RUN_MANIFEST.json before scoring; lock the contract and manifest checksums externally.

Limits: this is a four-case artifact-exchange/software-boundary campaign. No physical consequence, full provider/relay host compromise, concurrency, crash/reboot/power-loss, DDIL, delayed delivery, arbitrary missing-field matrix, implementation diversity, quorum, global clock ordering, secure network transport, signature-key theft, association-chain or universal absence claim. Successful composition here does not validate every feature or claim of the broader architecture. No READMEs, deletes, moves, commits or remote publication. CHECK_ME and the patent/reference handoff stay outside clean staging.
